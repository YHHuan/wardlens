# AI 連線、預覽與歷史趨勢

## 先連線，不必手打長 key

在「設定」按「用瀏覽器登入 OpenRouter」；若院內瀏覽器無法回到本機 callback，就展開「貼上 API key」，貼上一次並驗證儲存。Key 存入 Windows Credential Manager，不會回傳到網頁狀態。桌面備援的入口仍在「隱私與模型」。不要把 key 給協作者、寫進 EXE 或公開 GitHub；清空輸入框不等於清除系統剪貼簿。

「檢查連線 / 模型」只讀取 `/auth/key`、公開 `/models` 與 `/endpoints/zdr`，不傳病歷、不執行付費生成。成功不保證帳戶餘額、個別模型權限或生成可用。接著以合成 Demo 執行一次；HTTP 402 請核對 credits 或 key 上限。只有院方允許時才啟用外部 AI 與政策確認。

## v0.7：先看查房總覽，再問問題

「查房前整理」先顯示本機 TODO、生命徵象、用藥、報告與趨勢，不需送出 AI。「編輯病人資料」收合在各頁，可隨時展開；問題／病況框與回答則留在主畫面。查房可選「查房整理」、Admission Note 或自由提問；急症有獨立資料與問題草稿。AI 只使用該頁目前資料框的內容，不會把刪掉的來源附回。自行修改仍須對照 EMR。

上方「載入 / 更新資料」才連院內重新擷取。若已修改，覆蓋前會確認；抓取或生成中暫停編輯。切換病人會清除兩頁問題與回答，避免跨病人混用。資料框清空後，不會附上隱藏病歷。草稿只在本次工作階段；登出、結束或切換桌面備援不會保存它們。

回答以 Markdown 標題、清單與表格呈現；可「複製純文字」或展開「Markdown 原文」。內容以文字安全呈現，不執行模型產生的 HTML、腳本或遠端圖片。純文字複製只是移除排版語法，不代表病歷內容已通過核對。

背景 prompt 到「設定 → 開發者模式 → 開啟編輯器」修改。按「預覽並送出」先看去識別資料與本次模型，背景 prompt／完整 input 收在展開區；勾選本次確認後再按「確認送出」。預覽是唯讀，日常修改請返回資料與問題框。按「複製給其他 AI」也需通過同一份預覽；取消不會傳送。

## possible_long_identifier 不是網路卡住

這表示去識別檢查發現未標示的長數字，可能是病歷號、檢體編號、報告編號，也可能誤判臨床數值。未產生合格預覽前不會送出。

1. 按任一頁「預覽並送出」或「複製給其他 AI」。
2. 被擋時，預覽會提供「修正病人資料 / 問題」及背景 prompt；修正只留本機記憶體，原 EMR 不變。
3. 核對疑似識別碼，在修正框以遮罩文字取代。不要為了通過檢查而刪除有臨床意義的數字；不確定時回原資料核對。
4. 按「重新檢查」。仍有識別碼就繼續擋下，不能略過。
5. 通過後閱讀新的去識別預覽，確認模型及外部傳送。桌面備援仍有橘色標記與反白遮罩按鈕。

修改資料、問題、病人、模型或 prompt 後，舊預覽失效；移動游標／複製不會使預覽失效。修正只改本次預覽，不會覆寫主頁資料框；下次重建時會再檢查。修正內容不存檔、不寫進稽核；稽核只記 hash。通過檢查仍不是匿名化保證。

## 中文串流修正與錯誤碼

v0.4 的問題可用合成內容重現：`text/event-stream` 未指定 charset 時，Requests 會採用 ISO-8859-1；UTF-8 中文因此變成亂碼，其中部分字節又被當成換行而切壞 JSON。v0.5 直接讀取位元組，依 UTF-8 增量解碼，僅以 CR／LF 分行；支援跨封包中文字、BOM、心跳註解、多行 data 與最後的 usage 事件。[Requests 編碼行為](https://requests.readthedocs.io/en/latest/user/advanced/#encodings)、[SSE 標準](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)、[OpenRouter streaming](https://openrouter.ai/docs/api_reference/streaming)

真正的無效 UTF-8、壞 JSON、連線中斷或 tokens 用盡仍會標示不完整；不會丟掉壞片段後宣稱成功，也不會自動重送付費請求。若仍失敗，回報 `WL-SSE-UTF8`／`WL-SSE-JSON`／`WL-SSE-TYPE` 等代碼、模式與版本即可，不需病歷或原始回應。封裝自測會以合成中文串流跑過相同 client 與兩頁 UI，不代表實際帳戶或院內代理已驗收。

## 三個月不等於只有單日，也不保證全抓到

病人標題旁「回溯」預設 3 個月，可選 1／3／6／12。選完重新載入；已有 snapshot 不會因改選月份而變成新的範圍。桌面備援仍在左側設定。從 v0.3 升級時，舊的隱藏 60 個月預設改為 3；支援範圍內的自訂值保留。

- 生化／CBC 使用累積檢驗 endpoint，帶入數字月份。保留表格日期、時間、單位、數值及合併欄位，不以第一個日期假裝整張表只有單日。
- 已知檢驗／報告日期欄中的西元短年、民國三碼年與緊湊日期先轉成標準日期，避免把日期誤當長識別碼或錯置世紀；其他欄位的長數字不會擅自當成日期放行。
- 一般報告按涵蓋年度讀取索引，再依報告日期篩選。跨年會查兩年。未知日期的列保留並警示，不擅自判定不在範圍。
- 明細只追蹤院內索引回傳的連結，不猜報告網址；最多讀取最新 12 份。若明細不是預期報告結構，不能把選擇頁當全文。
- 病人總覽列出要求範圍與各來源辨識日期。這是文件內日期辨識，不是對完整歷史覆蓋的保證；報告日期也不是採檢時間。
- 有分頁、超過明細上限、無法讀取、日期不明、內容過大時明示。可縮小範圍重新載入，或回原 EMR 核對需要的舊報告，不能把未取得視為正常。

原本來源 30,000 字元與 prompt 每來源 24,000 字元的靜默截短已移除。現有保護上限：來源 200,000 字元／表格 10,000 列；AI input 每來源最多 120,000、來源內容總預算 240,000 字元，公平分配給每個來源。超限保留前後片段並加入 `SOURCE TRUNCATED`，不讓早期病歷耗盡預算而把後面的檢驗／報告完全藏掉。很寬的表格若被切開仍不可據此做完整比較，須核對原文。

## 趨勢表怎麼看

- **先看 WBC／Hb／PLT**：CBC 主表優先顯示這三項；需要時展開 differential。其餘生化與生命徵象分組，不把所有欄位塞進同一段文字。
- **先看變化，保留時間脈絡**：主列顯示依已知時間排序的近期數值、最後量測時間與跨度。詳細日期、原始值與來源可以展開；長時間空窗不能當成連續觀測。
- **數字來自來源表格**：表格與可繪製的迷你趨勢線由程式產生，不讓 LLM 猜值、補點或補正常範圍。線段只連接觀測點，不代表中間時間有量測。
- **不確定時直接列出**：單次結果不足以判定趨勢；未知時間另列，不當成最新值；不同單位分組。同時間矛盾值保留供核對，不任選一筆當正確答案。缺單位、含比較符號、時間不明或衝突時，不畫出看似精確的曲線。

內建查房 prompt 以一句摘要、少量重要問題、趨勢表與待確認事項為主，不在主文反覆列 SRC／hash／D±日碼。快速變化、舊數值、長空窗、介入前後仍需交代時間；CRP 下降本身不等於病人臨床改善。只有單日就寫無法判斷，不補造峰谷或 baseline。

Admission Note 仍依 CC、敘事式 HPI、PMH、Medications、Allergies、A/P 排序，保留重要缺漏與矛盾；未記錄過敏不會自行填 NKDA。急症維持先處置危急生理問題與叫支援。升級不覆寫自訂 prompt；既有自訂內容若仍要求 D 碼／SRC，需在開發者模式自行修改。

## 快慢模式與未完成回答

日常整理用 `fast` 或 `gemini_fast`；急症第一輪用 `emergency_fast`，同步床邊處置／叫支援。複雜或矛盾問題再用 `deep`、`claude_second`、`claude_deep` 或 `gemini_deep`。

v0.6.0 起七條路由預設都不傳 `max_tokens`，使用上游供應商預設；這不是無限輸出。開發者模式的 Max tokens 留白或填 0 即採此方式，亦可指定正整數。舊設定中與歷史內建值相同的額度會自動改成未指定；其他手動額度、模型與 prompt 保留。若仍想保留原內建數字，可於升級後重新儲存。[OpenRouter parameters](https://openrouter.ai/docs/api_reference/parameters)

Reasoning 與可見回答可能共用額度。回應達供應商／自訂上限、被過濾、缺少正常結束訊號或串流中斷時會標成不完整；不會自動續寫或重送產生費用。可縮小問題、降低 reasoning，或依模型支援指定較高 tokens 後手動重試。[OpenRouter reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

## 生命徵象

有本次住院序號時，另讀取 `findTpr` 的 `tprlist` 表，保留原表日期、時間、欄位與數值，供兩個 AI 工作區帶入。它是本次住院來源的快照，範圍不等於檢驗／報告的回溯月份，也不保證整段住院完整。多筆資料不會全部標成第一筆日期。未辨識 T／BP／HR／RR／SpO₂ 欄位、日期或來源失敗會明示；氧氣裝置／流量與最新床邊數值須另核對。內建查房 prompt 已加入此規則，既有自訂 prompt 不會覆蓋。

ZDR 與 `data_collection=deny` 是外部處理的資料政策限制，不是院內運算。送出時去識別內容仍會離開電腦，經 OpenRouter 與上游 provider 處理。[OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)
